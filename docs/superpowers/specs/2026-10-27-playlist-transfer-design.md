# Portable playlist audio

Approved: export original plus four prepared MP3 stems; import ZIP or extracted folder; Dropbox is handled manually. Expected archives are about 3 GB.

Catalog gets Import and per-collection Export links to /transfer. A top-level hosted transfer page owns native Save As and file/folder pickers so large exports stream directly to disk. A dedicated, exact-origin extension iframe exposes bounded transfer operations against the existing local library; no Spotify capture or transport. Extension IDs never enter the portable format. Versioned JSON records Spotify collection membership/order, track metadata, encoding gain/sample counts and per-file SHA-256/size. Audio stays byte-identical; artwork is embedded as bounded raster files when available, with source URL fallback on fetch failure.

ZIP uses zip.js sequential stored entries and ZIP64 as needed; import uses random-access BlobReader/File slices, never reads an entire archive into memory. Limits: 10,000 songs, 60,001 archive entries, 256 MB per audio file, 2 MB per cover, 16 MB manifest, 64 GB archive/unpacked total. Memory scales with one track, not playlist duration. Reject malformed paths, duplicates, unexpected payloads, missing files, unknown versions and invalid MP3 timing. Validated tracks commit atomically in IndexedDB. Register playlist before importing so partials appear; preserve existing complete tracks, replace captured/error/incomplete tracks only after validation. Processing/capture locks prevent concurrent replacement; per-track commits allow idempotent retry. Cancel never marks partial songs ready. Recheck storage quota in extension origin before each commit; handle real QuotaExceededError without losing completed tracks.

Full-playlist export requires all registered songs ready; partials show what remains. Controls show file/song/byte progress, cancellation and completion link. Import should work with an empty catalog and without downloading the model. File pickers stay top-level; no new extension permission. 6.7.0 contains the bounded storage relay; packaging and hosted deployment follow tests. No Store submission is implied.

Verify metadata validation, corrupt/missing files, ZIP/folder round trips, duplicate imports, incomplete replacement, quota failures, cancellation, origin isolation, >4 GB ZIP64 boundary and a real 3 GB sequential stream exercise. UI checks use a synthetic fixture, not deletion/import into the user's real library. Existing playback regressions must pass.
