# Extension staging and automatic website imports

Approved in conversation: keep the full Spotify capture overlay, separate in its hosted web worker while subsequent songs capture, and transfer staged originals/stems to the standalone website automatically. The website owns the lasting library. No offscreen document, storage-access prompt, new extension permission, or embedded track player.

The extension keeps verified raw captures until either the website imports them or the hosted overlay commits a validated five-file MP3 result. Processing and raw importing use expiring, token-bound claims in IndexedDB. Live processing renews its claim; a closed/crashed overlay releases ownership by timeout. Only the owning Spotify overlay can process its captures. Prepared results are immutable, readable by the trusted standalone website, and deleted only after a durable website receipt acknowledges the exact result ID.

Import runs continuously while a website page is open. It handles metadata membership independently, resumes bounded chunks from IndexedDB after interruption, validates file size/hash/MP3 timing, then commits song files, metadata, membership and receipt atomically. Source audio survives failures and quota errors. A retry after a lost acknowledgment uses the receipt, not another copy. Already-ready songs retain their website audio; their validated duplicate staging can be acknowledged after membership and receipt commit. Partial recordings are never exported. No whole-playlist allocation; work is bounded to one song and one compressed file for validation.

Overlay progress reflects capture, separation, and prepared/website status. Captured source metadata carries title, artist, artwork URL, timing and gain; available artwork bytes are included in prepared imports. Settings allow pausing/resuming separation. Closing the overlay cancels its inference worker and releases its raw claim without dropping audio. Imports must not race the website's existing separation worker.

Verification: mutual exclusion, lease expiry/token replacement, interrupted upload/import, chunk retry integrity, MP3 mismatch, receipt-before-delete, ack failure retry, metadata/artwork/membership preservation, sender restrictions, and existing full tests/lint/build. Deployment requires an extension reload; do not claim a live capture test without observing it.
