# Standalone playlists and overlay recovery

Catalog rows retain their Spotify link and add an Open in ktv420 link. `/playlist?id=album.ID` or `playlist.ID` hosts the existing extension storage broker and the existing hosted LibraryPage in standalone mode. The extension still owns local audio; nothing is uploaded or duplicated. Only exact ktv420 origin is added to the broker parent allowlist. Standalone mode rejects capture, listening heartbeats, and Spotify transport at the bridge. Catalog metadata is read using a narrow external message; audio travels only via the existing authenticated iframe library protocol.

The stored collection order drives rows; prepared tracks open the same player, effects, visualizers, recording and preferences. Missing tracks stay disabled. One-based `ktv420=N` selects a prepared track paused; browser Back/Forward works. Own view changes update history without re-entering the paused-entry path; automatic advancement autoplays. X/Escape pauses and returns to catalog; Spotify's X still closes its overlay. Standalone k opens the first prepared track, or returns from a track to its playlist. Invalid IDs, absent collections and absent/old extensions show concise recovery links.

Overlay debugging reproduced a hidden player that never finishes its handshake; an empty srcdoc attribute was observed on its frame, but its writer is unconfirmed.
