# Independent DJ tempo and pitch

Approved with yesi. Add two compact controls beside playback: Tempo 0.50–1.50× in 0.01 steps and Pitch −12–+12 semitones in whole steps. Clicking the displayed value resets that control. Tempo preserves pitch; pitch preserves tempo. Apply both to original and stems with a common audio clock. Capture and saved files remain at original speed and pitch. Scene slots are not part of this task.

Use a locally served, pinned time-stretch/pitch-shift implementation running off the UI thread. Keep DSP and playback-clock concerns outside the Player component. Handle processor failures explicitly instead of falling back to pitch-changing playback. Do not repeatedly regenerate or save transformed audio. Preserve seeking, pause, track endings, effects, visualizer timing and aligned stem starts across changes. Default settings should retain untransformed playback quality where the engine permits.

Extend the existing page-media bridge to set and verify Spotify's local media rate while ready stems play. Spotify remains silent; its pitch need not be changed. Do not use Spotify APIs. Restore 1× before any capture, unprepared song or ownership teardown; captures reject non-1× audio. A rejected/reset playback rate must stop the altered playback with an actionable message rather than allow drift. Expose capability so old installed extensions request an update for tempo support.

Record the initial tempo/pitch and subsequent changes in mixer snapshots. Introduce a new recording version for these semantics so old players reject rather than silently misplay it; new players accept v2 recordings with neutral defaults. Replay timing remains elapsed performance time, while song position advances according to tempo. Apply changes to Spotify and local playback without losing pause/seek or track transition semantics. Independent recipient master volume remains unchanged.

Validate DSP duration and output pitch independently using actual processor output, neutral playback, shared stem timing, speed changes, pause/seek/end and source-clock integration. Exercise record/replay with changes and legacy defaults. Run tests/lint/build and browser fixture, inspect compact UI and production packaging. Document real-Spotify compatibility separately from fixture evidence. Publish only completed work; preserve extension installation directory and package a new extension release.
